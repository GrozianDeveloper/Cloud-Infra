# Authentik SSO for Home Assistant

HA has no built-in OIDC. Use HACS [hass-oidc-auth](https://github.com/christiaangoossens/hass-oidc-auth). Do **not** put Authentik FA on this vhost (breaks Companion + MCP).

Official Authentik notes: https://integrations.goauthentik.io/miscellaneous/home-assistant/

Optional extra HA OS VM(s): one OIDC app per VM. Catalog Home Assistant (if any) is a separate app. Bind a group from `instance/maps/permissions` — do not grant the app to a user directly.

Scripts from `.cursor/skills/authentik` (do not curl). Creds: `instance/{HA_SLUG}/.env.oidc` (never print).

## Authentik

Create Application + OIDC Provider (`create-oidc-app.py`):

- Slug `{HA_SLUG}`, launch `https://{HA_DOMAIN}`
- Redirect (strict): `https://{HA_DOMAIN}/auth/oidc/callback`
- Scopes: `openid`, `email`, `profile`, `groups`
- Bind: the instance map group for this VM (Group Binding only)

Discovery: `https://{AUTH_DOMAIN}/application/o/{HA_SLUG}/.well-known/openid-configuration`

## Caddy

Vhost `{HA_DOMAIN}` → `{HA_UPSTREAM}` (HA HTTP port; default `:8123`). No FA. If Caddy cannot reach the VM from `proxy`, use a host-net gateway (`caddy/README.md`).

```bash
bash caddy/scripts/push.sh
bash caddy/scripts/reload.sh
```

## DNS + TLS

If `{HA_DOMAIN}` is outside the main split-horizon wildcard, it needs its own AdGuard rewrite **and** public A/AAAA. Otherwise ACME never issues a cert (HTTP 308 on `:80`, TLS `internal error` on `:443`).

## Home Assistant (on the VM)

Trusted proxies + HACS are on the VM. Finish OIDC:

Caddy sends `X-Forwarded-For`. `trusted_proxies` must include the **Caddy host LAN IP** (the TCP peer HA sees). Trusting only Docker `172.16.0.0/12` is not enough when a host-net gateway is used — HA returns `400` (blank page).

1. Network: External URL = `https://{HA_DOMAIN}`. Internal URL = LAN HTTP URL (port as on that VM).
2. HACS → **OpenID Connect/SSO Authentication** (`christiaangoossens/hass-oidc-auth`). Restart if asked.
3. Settings → Devices & services → Add → OpenID Connect/SSO Authentication → Authentik.
4. Discovery URL + client id/secret from `instance/{HA_SLUG}/.env.oidc`.
5. Roles: admin group = the Authentik group bound in the instance map. Leave user role empty.
6. Local backup login: `https://{HA_DOMAIN}/?skip_oidc_redirect=true`

Do not leave `features.automatic_user_linking` on after a short migration.

## MCP

LAN token only — see that VM's `{app}/MCP.md`. Do not send MCP through Caddy/OIDC. Expose entities to Assist or tools are empty.
