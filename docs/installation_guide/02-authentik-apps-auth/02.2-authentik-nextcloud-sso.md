# Authentik SSO for Nextcloud (via `user_oidc` app)

Use the official Nextcloud OpenID Connect app — not Social Login (session bug with Authentik on NC 34).

Emergency local login: `https://{NEXTCLOUD_DOMAIN}/login?direct=1`

Do not curl Authentik — skill scripts only (`.cursor/skills/authentik/SKILL.md`). Creds from `instance/{app}/.env`. Never print secrets.

## In Authentik

### A. Scope mapping — profile + `user_id`

Bootstrap deploys scope mapping **Nextcloud profile** (`scope_name: nextcloud`). Logic (expression in [`authentik-create-nextcloud_oidc.py`](../../../master-nextcloud-aio/scripts/oidc/authentik-create-nextcloud_oidc.py)):

- **Phone:** from `user.username` when 10+ digits (`8…` → bare digits, else `+{username}`)
- **Organisation / role:** from Nextcloud application entitlement `attributes` (`organization`, `role`); omitted if unset
- **Role priority:** when several entitlements define `role`, first match in `ENTITLEMENT_PRIORITY` (in the script) wins
- **Quota:** sum of all entitled `quota` values (parsed as bytes); omitted if none; emit as string (e.g. `90 GB`)
- **User overrides:** `user.attributes.info` (`organization`, `role`, `country`, `birthday`) and `settings` (`locale`, `language`, `region`) beat entitlement values
- **Defaults** (language, locale, region, locality, username prefix): instance values in that script — not this file
- **No default organisation** — set `organization` on entitlements or `info.organization` on the user

Re-run bootstrap (Authentik REST):

```bash
python3 master-nextcloud-aio/scripts/oidc/authentik-create-nextcloud_oidc.py
```

Writes `instance/master-nextcloud-aio/.env.oidc` (client id/secret). Idempotent.

Bootstrap also PATCHes entitlement attributes (`role`, `organization`, `quota`) from `ENTITLEMENT_ATTRS` in the script. Edit that dict for this instance, then re-run.

For an existing NC account (e.g. `admin`), set Authentik user attribute `nextcloud_user_id`:

```bash
python3 .cursor/skills/authentik/scripts/set-user-attribute.py --user <authentik-username> --key nextcloud_user_id --value admin
```

### B. Application entitlements

On each Nextcloud application entitlement, optional attributes:

| Attribute | Purpose |
|-----------|---------|
| `role` | Nextcloud profile role |
| `organization` | Nextcloud profile organisation |
| `quota` | Per-user storage limit (string, e.g. `200 GB`) |

Example shape (values from `instance/maps/permissions`):

```json
{
  "role": "<role>",
  "organization": "<org>",
  "quota": "200 GB"
}
```

### C. OIDC provider

`Applications > Providers` — edit **nextcloud**:

- Auth flow: `default-authentication-flow`
- Authorization flow: `default-provider-authorization-explicit-consent`
- Client type: `Confidential`
- Signing Key: `authentik Self-signed Certificate` (required)
- Encryption Key: **leave empty** — `user_oidc` cannot decrypt encrypted id_tokens (RSA-OAEP-256 → Internal Server Error)
- Scopes (property mappings): `openid`, `profile`, `email`, `entitlements`, `Nextcloud profile`, **`offline_access`** (required for refresh tokens since Authentik 2024.2)
- Grant types: `authorization_code`, `refresh_token`
- Access token validity: `minutes=15`
- Refresh token validity: `days=35`
- Refresh token threshold: `days=17`
- Access code validity: `minutes=1;seconds=30`
- Redirect URIs (Authorization):
  ```
  https://{NEXTCLOUD_DOMAIN}/apps/user_oidc/code
  https://{NEXTCLOUD_DOMAIN}/index.php/apps/user_oidc/code
  ```
- Redirect URIs (Logout) — required since Authentik 2026.5+ for RP-initiated logout:
  ```
  https://{AUTH_DOMAIN}/if/user/
  ```
  Post-logout landing page (Authentik user library). Type **Logout**, strict match.
  Legacy NC URLs (`https://{NEXTCLOUD_DOMAIN}`, `/login`) may remain whitelisted but are unused.
- Invalidation flow: `default-invalidation-flow` — ends Authentik session on Nextcloud logout (nextcloud provider only; other apps unchanged)
- Logout URI (Back-channel): `https://{NEXTCLOUD_DOMAIN}/apps/user_oidc/backchannel-logout/1`
- Logout method: `Back-channel`

Discovery URL:

```
https://{AUTH_DOMAIN}/application/o/nextcloud/.well-known/openid-configuration
```

## Session stability

Bootstrap sets Authentik OAuth token TTLs and `offline_access` on the nextcloud provider, and extends `default-authentication-login` session to 35 days with remember-me prompt hidden (`remember_me_offset=seconds=0`; affects all apps using that flow).

After deploy, **each user must log out and log back in once** so Nextcloud stores a refresh token.

| Layer | Setting | Value |
|-------|---------|-------|
| Authentik OAuth | access / refresh / threshold | 15 min / 35 days / 17 days |
| Authentik browser | `default-authentication-login` | 35 days, no remember-me prompt |
| Nextcloud | `store_login_token` | `1` |
| Nextcloud | `session_lifetime` | 3024000 (35 days) |
| Nextcloud | `remember_login_cookie_lifetime` | 3024000 (35 days) |

Verify:

```bash
python3 master-nextcloud-aio/scripts/oidc/authentik-create-nextcloud_oidc.py
docker exec -u 33 nextcloud-aio-nextcloud php occ config:app:get user_oidc store_login_token
docker exec -u 33 nextcloud-aio-nextcloud php occ config:system:get session_lifetime
```

## Profile & quota notes

- Quota claim must be a **string** (`15G`, `200 GB`); integer JSON values often fail in `user_oidc`.
- OIDC per-user quota (sum of entitlements) updates on each login; [`apply-group-quotas.sh`](../../../master-nextcloud-aio/scripts/apply-group-quotas.sh) sets group defaults when `occ group:addsetting` exists.
- Timezone is not provisioned via `user_oidc`.
- Property mapping **Test** in Admin UI does not pass `provider`; expression falls back to Nextcloud app by slug — test should work without extra context.

## Logout

After Nextcloud logout, users land on `https://{AUTH_DOMAIN}/if/user/` (not Nextcloud). Bootstrap sets nextcloud provider **Invalidation flow** to `default-invalidation-flow` so the Authentik session ends and NC does not silently re-login.

## Notes

- Do **not** enable server-side encryption with OIDC.
- Groups sync from Authentik `entitlements` claim (ancestor closure — [06-groups-map.md](06-groups-map.md)).
- `allow_local_remote_servers` is already `true` in AIO config.
